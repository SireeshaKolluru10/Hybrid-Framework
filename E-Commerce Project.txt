🧪 3. Manual Test Cases for E-Commerce Project
================================
Below are sample manual test cases grouped by module (you can list 8–10 per section in resume or test documents).

🧍‍♀️ User Management

Verify user can register with valid details.

Verify email format validation in registration.

Verify password strength and mismatch scenarios.

Verify login with valid/invalid credentials.

Verify forgot password flow (email reset link).

Verify logout clears the session.

🛒 Product Catalog

Verify all categories and subcategories display correctly.

Verify search functionality returns accurate results.

Verify sorting (price low-high, high-low).

Verify product filters (brand, size, color) work correctly.

Verify pagination works properly.

📦 Product Details

Verify product image zoom, multiple images view.

Verify product description and price are correct.

Verify "Add to Cart" and "Buy Now" buttons work.

🧺 Shopping Cart

Verify adding multiple products to cart.

Verify updating product quantity.

Verify removing a product from the cart.

Verify total price calculation is correct.

💳 Checkout & Payment

Verify user can add a new address.

Verify order summary displays correct details.

Verify payment success and failure flows.

Verify COD option appears when eligible.

📦 Order Management

Verify placed orders appear in order history.

Verify order cancellation works.

Verify tracking info updates properly.

⚙️ Admin Module

Verify admin can login.

Verify admin can add/edit/delete products.

Verify admin can see order reports.

✉️ Notifications

Verify confirmation email is sent post order.

Verify password reset email contains correct link.

🤖 4. Automation Test Cases (Selenium + Java + TestNG)

Automation focuses on regression-prone, repetitive, and UI-driven flows.

🔑 Login & Registration

Automate registration with valid & invalid data (Data-Driven).

Automate login with multiple credential sets (Excel).

Verify successful logout redirects to login page.

🧭 Navigation & Product Catalog

Verify product search (assert product titles).

Verify sorting/filtering functionality.

Verify category navigation works (use Page Objects).

🛍️ Cart and Checkout

Add product to cart → validate item count.

Update quantity → verify total changes.

Remove product → verify cart empty message.

Checkout with valid details (simulate dummy payment).

📑 Order and Payment

Verify successful order placement message.

Capture order number and validate in Order History page.

🧰 Admin Module (optional automation)

Login as admin and add new product.

Verify product appears in user catalog.

🧾 Reports / Assertions

Generate Extent Report for all test cases.

Capture screenshots on failure.

Log events with Log4j.

🧱 3️⃣ What kind of framework did you use, and why did you choose it?

Sample Answer:

“We used a Hybrid framework combining Page Object Model and Data-Driven approaches.
POM helped us separate UI locators and actions into different classes for maintainability, while Data-Driven allowed us to use different sets of test data from Excel using Apache POI.
This structure made our framework reusable, modular, and easy to scale.”

🧰 4️⃣ How do you handle test data in automation?

Sample Answer:

“We used Excel sheets for test data and accessed them through Apache POI in our scripts.
The data was parameterized and environment-specific, so I created a utility method that fetched the right data based on the environment.
This helped in maintaining consistency and reduced manual updates.”

🧩 5️⃣ How do you handle synchronization issues in Selenium?

Sample Answer:

“I prefer using explicit waits with WebDriverWait or ExpectedConditions instead of implicit waits.
This ensures that the script waits for specific elements to become visible or clickable, reducing flaky test failures.
In some cases, I’ve used FluentWait for polling with timeout intervals.”

🔁 6️⃣ How do you manage test execution in Jenkins?

Sample Answer:

“Our project was integrated with Jenkins for CI/CD.
We configured Maven build jobs in Jenkins that triggered automation runs whenever a new build was deployed.
The TestNG suite was executed automatically, and the HTML report was generated and sent via email to the team.
I also monitored Jenkins logs and build history to verify job stability.”

🔐 7️⃣ How do you handle exceptions or failures in Selenium scripts?

Sample Answer:

“I used try-catch blocks to handle exceptions gracefully and implemented a custom listener class using TestNG’s ITestListener interface to capture screenshots on failure.
This helped in debugging failed cases and made the test reports more informative.”

🧪 8️⃣ How do you select which test cases to automate?

Sample Answer:

“We focused on high-priority, repetitive, and regression-prone test cases that took a lot of time in manual execution.
Scenarios with stable UI and predictable outcomes were prioritized, while exploratory and UI-changing areas were left for manual testing.”

🧱 9️⃣ How do you ensure your framework is maintainable and scalable?

Sample Answer:

“I follow POM design principles, keep locators and business logic separate, and use utility/helper classes for common functions like browser setup, waits, and screenshots.
I also use Maven for dependency management and maintain a clear folder structure so that new test cases can be added easily.”

🧩 10️⃣ What are some best practices you follow in automation?

Sample Answer:

“Some of the best practices I follow include keeping locators unique and stable, using meaningful method names, implementing reusable utilities, version controlling via Git, and integrating with CI/CD for regular execution.
I also maintain proper logging and reporting for better traceability.”

⚡ 11️⃣ How do you debug failed automation scripts?

Sample Answer:

“First, I check the error logs and screenshots generated during execution.
Then, I reproduce the issue manually to confirm if it’s a script or application issue.
If it’s script-related, I review locators, waits, or data dependencies, and rerun after applying fixes.
For Jenkins failures, I check environment configurations or browser setup.”
